# Refactor proof: `evaluate_slate` extraction is pick-identical

Generated by `.venv/bin/python scripts/proof_slate_identity.py` (offline; reads `data/games/games.csv` + `data/odds/lines.csv`, no network, no API credits).

PR 3a moved the per-slate evaluation loop out of `pipeline._strategy_picks` into `strategy/slate.py::evaluate_slate`. That loop decides every live pick, so this replays the pre-refactor loop and the extracted one over the same captured history with the same inputs and compares the ledger rows they emit, field for field (`created_ts_utc` excluded — `pick_row` stamps it from the clock, so it differs between two runs of identical code).

Scenarios compared: **2920** — every enabled live strategy x 73 captured slate days x two cutoff shapes (whole-slate and a pinned live cutoff) x two windows (16:00, 23:59) x two budgets (uncapped, 2). Picks emitted across them: **5213**.

**Mismatches: 0.**

| strategy | picks emitted | result |
|---|---|---|
| `fade_public` | 867 | identical |
| `fav_ml` | 2110 | identical |
| `pv_orig` | 104 | identical |
| `pv_v3` | 1466 | identical |
| `sharp_split` | 666 | identical |

The splits staleness clock is pinned per day to that day's own capture time: `splits_signal._splits_guards` ages captured splits against `now_utc()`, so an unpinned comparison straddles the staleness boundary and goes flaky.
